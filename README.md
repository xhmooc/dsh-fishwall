>

>
> 这个是我平时的上班电脑。我赶忙去看我整理好的文档，看到的只剩下断壁残垣：本来满满当当的文件夹，只剩下俩文件夹里的俩文件。我上班几年来全部的资料，直接消失了。

> 最可怕的还有——他已经在动我的 OneDrive 了。

## 我查到了什么

**什么都没有。**

真的。我一样一样去翻：

- **回收站**？空的。不是资源管理器删的，不会进回收站。
- **卷影副本**？没有。
- **USN 变更日志**？已经回卷了，最早只到重启之后。
- **进程创建审计（4688）**？那天没开。
- **对象访问审计（4663）**？也没开。

我手上唯一的"证据"，是一个 263 KB 的 `python.exe`——在 `.venv` 目录里，整个虚拟环境被删得只剩它一个。因为**它当时正在跑，Windows 不让你删正在用的文件**。

它的目录时间停在 `11:58:51`。

那一刻我坐在电脑前，看着一个个目录变空，什么都做不了。事后想找个人骂都找不到——因为**根本不知道是谁**。

这不行。

## 所以我写了个东西

一句话：**盯着你电脑上删文件的速度，谁删得太快就把谁按住。**

```
① 先把 Windows 的文件审计打开（auditpol + SACL）
② 每隔几秒看一眼审计日志：刚才这一小段时间，删了多少个？
③ 超过阈值 → taskkill 掉正在删的那个进程
④ 不管杀没杀成，都写一份事故记录：谁、多少次、删了哪些路径
```

不是"防删除"——删除拦不住。它做的是**止损 + 破案**：

- 你不用再猜是谁干的，日志里有 PID
- 你不用再等它删完，超速那一刻就被按住
- 你不用再怕"过几天就查不到"，事故记录是文件，躺在硬盘上

**留下证据，比什么都重要。**

## 装

```bash
dsh plugin --profile <你的 profile> add dsh-fishwall
```

**装完完全退出 DSH 再打开**（设置页那一半是重启时加载的）。

要**管理员权限**——`auditpol` 和 `Set-Acl` 都要。没权限它也能跑，只是读不到事件，等于睁眼瞎。

---

## 装完你会看到

设置里多一项 **「删除防护」**：

- 顶上一条状态：`监控中` / `已暂停（只记录）`
- 几个数字：检测窗口、外部进程阈值、DSH 自身阈值、冷却时间
- 几个开关：要不要真动手、要不要连 DSH 一起杀
- 一个按钮：**暂停（维护用）**
- 底下：最近几次事故——时间、原因、杀了谁

阈值都能改，改完两秒生效。

---

## 三个你必须知道的坑

**① 装插件之前，先按暂停。**

```powershell
New-Item "$env:USERPROFILE\.dsh\fishwall.pause" -ItemType File -Force   # 暂停
Remove-Item "$env:USERPROFILE\.dsh\fishwall.pause" -Force               # 恢复
```

或者直接在设置页点「暂停」。

为什么？因为 `pnpm install` 重建 `node_modules` 的时候，几秒钟能删上千个文件，进程是 `node.exe`——**它会把自己人当事故打掉**。我实测过，真的会。

**② 它默认会杀 DSH 自己。**

听着很疯，但插件是在 DSH 进程里跑的。进程内的插件发疯，你只有两条路：杀掉 DSH，或者看着它删完。

所以 `killDsh` 默认开着，阈值给到 1500 个 / 30 秒——正常写文件到不了这个数。你觉得太激进，设置页里关掉就行，它就只记录不动手。

**③ 它救不回已经删掉的东西。**

它是个刹车，不是时光机。删掉的就是删掉了，它只能保证「不再继续删」和「你知道是谁」。

## 配置

`~/.dsh/fishwall.json`，也可以在设置页里改：

```json
{
  "enabled": true,
  "intervalMs": 2000,
  "windowSec": 30,

  "threshold": 300,
  "dshThreshold": 1500,

  "cooldownSec": 300,
  "kill": true,
  "killDsh": true,

  "allow": ["explorer.exe"],
  "autoAudit": true,

  "roots": [
    "C:\\Users\\<你>\\.dsh",
    "C:\\Users\\<你>\\Desktop",
    "C:\\Users\\<你>\\Documents",
    "C:\\Users\\<你>\\Downloads"
  ]
}
```

| 键 | 意思 |
|---|---|
| `threshold` | 外部进程：30 秒内删这么多 → 按住 |
| `dshThreshold` | DSH 自己：给它更高的容忍度 |
| `kill` | 关掉 = 只看不动手，纯粹观察 |
| `killDsh` | 能不能杀 DSH 自己（唯一能拦住进程内发疯的手段） |
| `allow` | 白名单。默认放行资源管理器——你自己删东西不算事故 |
| `roots` | 盯哪几个目录。不在里面的删了它也看不见 |

**永远不会碰的进程**：`System`、`csrss`、`wininit`、`services`、`lsass`、`smss`、`winlogon`、`svchost`、`dwm`、`explorer`。

## 文件都在哪

| | |
|---|---|
| 配置 | `~/.dsh/fishwall.json` |
| 日志 | `~/.dsh/fishwall.log` |
| 事故 | `~/.dsh/fishwall-incidents/*.json` |
| 暂停标记 | `~/.dsh/fishwall.pause` |

事故记录长这样，一行都不用猜：

```json
{
  "at": "2026-10-30T08:55:25.818Z",
  "why": "30s 内 60 次删除（阈值 20）",
  "totalEvents": 60,
  "offenders": [
    { "pid": 21156, "process": "node.exe", "count": 60,
      "sample": ["C:\\...\\g1.txt", "C:\\...\\g0.txt"] }
  ],
  "killed": [{ "pid": 21156, "process": "node.exe" }],
  "dryRun": false
}
```

## 它不行的地方

我先把丑话说前面：

- **只支持 Windows**。靠的是 4663 事件，别的系统没有。
- **要管理员**。没权限就是睁眼瞎。
- **只看 `roots` 里那几个目录**。别的地方删，它不知道。
- **算的是速度，不是总量**。慢慢删、低于阈值，它不管——所以它防的是"疯狂删"，不是"删一个"。
- **杀进程 ≠ 撤销删除**。已经没了的就是没了。

还有一条最现实的：**如果你的盘本来就在坏**（比如 NVMe 掉盘），它帮不上忙。这种情况它只会看见"删除"，然后杀一个根本不该杀的进程。**先看盘的健康度，再看这个。**
